# Basmati Backend Development Guide

## Project Overview

Basmati is a web-based calendar and event management application similar to Teamup. This guide covers **backend development only** using a microservices architecture.

## Technology Stack

- **Language**: Python 3.11+
- **API Framework**: FastAPI
- **Database**: MongoDB Atlas (cloud)
- **Deployment**: Docker (all services containerized)
- **Code Style**: snake_case for methods and variables
- **Documentation**: English for code, Spanish for comments

## Development Requirements

### General Rules

1. **Everything must be dockerized** - each microservice runs in its own container
2. **Each microservice must run on a different port**
3. **All methods must have docstrings** with:
   - Parameter descriptions
   - Return value descriptions
   - Example requests/responses for FastAPI interactive docs
   - Comments in Spanish, code in English
4. **OpenAPI specification** auto-generated by FastAPI
5. **MongoDB connection string** provided via environment variables

## Microservices Architecture

### 0. API Gateway (Port 8000)

**Responsibilities**:
- Single entry point for all client requests
- Request routing to appropriate microservices
- Request/response validation
- Cross-cutting concerns (logging, error handling)

**Features**:
- Routes all API requests to backend services
- Centralizes API versioning (`/v1/`, `/v2/`)
- Aggregates responses from multiple services
- Handles request/response transformation

**Required Endpoints**:
- All endpoints are proxied to backend services
- `GET /docs` - FastAPI interactive documentation
- Health check: `GET /health`

**Environment Variables**:
- `SERVICE_PORT=8000`
- `USER_SERVICE_URL=http://user-service:8001`
- `CALENDAR_SERVICE_URL=http://calendar-service:8002`
- `EVENT_SERVICE_URL=http://event-service:8003`
- `NOTIFICATION_SERVICE_URL=http://notification-service:8004`
- `SEARCH_SERVICE_URL=http://search-service:8005`
- `INTEGRATION_SERVICE_URL=http://integration-service:8006`

---

### 1. UserService (Port 8001)

**Responsibilities**:
- User CRUD operations
- User preference management
- Basic user profile queries

**Required Endpoints**:
- `POST /users` - Create user
- `GET /users/{user_id}` - Get user by ID
- `PUT /users/{user_id}` - Update user
- `DELETE /users/{user_id}` - Delete user
- `GET /users/search?email={email}` - Search by email (parametrized query 1)
- `GET /users/search?name={name}` - Search by partial name (parametrized query 2)

**Environment Variables**:
- `MONGO_URI`
- `SERVICE_PORT=8001`

---

### 2. CalendarService (Port 8002)

**Responsibilities**:
- Calendar CRUD operations
- Hierarchical calendar relationships
- Calendar search and filtering

**Required Endpoints**:
- `POST /calendars` - Create calendar
- `GET /calendars/{calendar_id}` - Get calendar by ID
- `PUT /calendars/{calendar_id}` - Update calendar (only by organizer)
- `DELETE /calendars/{calendar_id}` - Delete calendar (only by organizer)
- `GET /calendars/search?organizer_id={user_id}` - Get calendars by organizer (parametrized query 1)
- `GET /calendars/search?keywords={keyword}` - Search by keywords (parametrized query 2)
- `GET /calendars/{calendar_id}/children` - Get child calendars (relationship query 1)
- `GET /calendars/{calendar_id}/hierarchy` - Get full calendar hierarchy (relationship query 2)

**Environment Variables**:
- `MONGO_URI`
- `SERVICE_PORT=8002`
- `USER_SERVICE_URL=http://user-service:8001`

---

### 3. EventService (Port 8003)

**Responsibilities**:
- Event CRUD operations
- Event content management (attachments, comments)
- Trigger notifications on comments

**Required Endpoints**:
- `POST /events` - Create event
- `GET /events/{event_id}` - Get event by ID
- `PUT /events/{event_id}` - Update event
- `DELETE /events/{event_id}` - Delete event
- `POST /events/{event_id}/comments` - Add comment (triggers notification)
- `POST /events/{event_id}/attachments` - Add attachment URL
- `GET /events/search?calendar_id={calendar_id}` - Get events by calendar (parametrized query 1)
- `GET /events/search?date_range?start={start}&end={end}` - Get events by date range (parametrized query 2)
- `GET /events/{event_id}/comments/users` - Get users who commented on event (relationship query 1)
- `GET /users/{user_id}/commented_events` - Get events user commented on (relationship query 2)

**Environment Variables**:
- `MONGO_URI`
- `SERVICE_PORT=8003`
- `NOTIFICATION_SERVICE_URL=http://notification-service:8004`
- `CALENDAR_SERVICE_URL=http://calendar-service:8002`

### 4. NotificationService (Port 8004)

**Responsibilities**:
- Create and manage notifications
- Send email notifications
- Mark notifications as read

**Required Endpoints**:
- `POST /notifications` - Create notification (called by EventService)
- `GET /notifications/user/{user_id}` - Get user notifications
- `PUT /notifications/{notification_id}/read` - Mark as read
- `GET /notifications/search?user_id={user_id}&read=false` - Get unread notifications (parametrized query 1)
- `GET /notifications/search?event_id={event_id}` - Get notifications for specific event (parametrized query 2)

**Environment Variables**:
- `MONGO_URI`
- `SERVICE_PORT=8004`
- `USER_SERVICE_URL=http://user-service:8001`
- `EMAIL_SERVICE_API_KEY` (optional for now)

---

### 5. SearchService (Port 8005)

**Responsibilities**:
- Advanced search across calendars and events

- Aggregated search results

**Required Endpoints**:
- `GET /search/calendars?q={query}` - Full-text search calendars (parametrized query 1)
- `GET /search/events?q={query}` - Full-text search events (parametrized query 2)
- `GET /search/combined?q={query}` - Search both calendars and events
- `GET /search/calendars/by_organizer?organizer_name={name}` - Find calendars by organizer name (relationship query 1)
- `GET /search/events/by_calendar_title?title={title}` - Find events by calendar title (relationship query 2)

**Environment Variables**:
- `MONGO_URI`
- `SERVICE_PORT=8005`
- `CALENDAR_SERVICE_URL=http://calendar-service:8002`
- `EVENT_SERVICE_URL=http://event-service:8003`

### API Gateway Implementation

```python
# api-gateway/main.py
from fastapi import FastAPI, Request, HTTPException
from fastapi.responses import JSONResponse
import httpx
import os
from typing import Optional

app = FastAPI(
    title="Basmati API Gateway",
    description="Punto de entrada centralizado para todos los servicios de Basmati",
    version="1.0.0"
)

# Configuración de servicios backend
SERVICES = {
    "users": os.getenv("USER_SERVICE_URL", "http://user-service:8001"),
    "calendars": os.getenv("CALENDAR_SERVICE_URL", "http://calendar-service:8002"),
    "events": os.getenv("EVENT_SERVICE_URL", "http://event-service:8003"),
    "notifications": os.getenv("NOTIFICATION_SERVICE_URL", "http://notification-service:8004"),
    "search": os.getenv("SEARCH_SERVICE_URL", "http://search-service:8005"),
    "integrations": os.getenv("INTEGRATION_SERVICE_URL", "http://integration-service:8006"),
}

@app.get("/health")
async def health_check():
    """
    Verifica el estado del API Gateway y sus servicios.
    
    Returns:
        dict: Estado del gateway y disponibilidad de servicios
    """
    return {"status": "healthy", "service": "api-gateway"}

async def proxy_request(service_name: str, path: str, request: Request):
    """
    Proxifica una petición al servicio backend correspondiente.
    
    Args:
        service_name: Nombre del servicio destino
        path: Ruta dentro del servicio
        request: Petición original del cliente
        
    Returns:
        JSONResponse: Respuesta del servicio backend
    """
    if service_name not in SERVICES:
        raise HTTPException(status_code=404, detail=f"Servicio {service_name} no encontrado")
    
    service_url = SERVICES[service_name]
    full_url = f"{service_url}/{path}"
    
    try:
        async with httpx.AsyncClient() as client:
            response = await client.request(
                method=request.method,
                url=full_url,
                headers=dict(request.headers),
                content=await request.body()
            )
            return JSONResponse(
                status_code=response.status_code,
                content=response.json() if response.text else {}
            )
    except httpx.ConnectError:
        raise HTTPException(
            status_code=503,
            detail=f"No se pudo conectar con {service_name}"
        )
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))

# Rutas para cada servicio
@app.api_route("/users/{path:path}", methods=["GET", "POST", "PUT", "DELETE"])
async def users_route(path: str, request: Request):
    """Proxifica peticiones al servicio de usuarios"""
    return await proxy_request("users", path, request)

@app.api_route("/calendars/{path:path}", methods=["GET", "POST", "PUT", "DELETE"])
async def calendars_route(path: str, request: Request):
    """Proxifica peticiones al servicio de calendarios"""
    return await proxy_request("calendars", path, request)

@app.api_route("/events/{path:path}", methods=["GET", "POST", "PUT", "DELETE"])
async def events_route(path: str, request: Request):
    """Proxifica peticiones al servicio de eventos"""
    return await proxy_request("events", path, request)

@app.api_route("/notifications/{path:path}", methods=["GET", "POST", "PUT", "DELETE"])
async def notifications_route(path: str, request: Request):
    """Proxifica peticiones al servicio de notificaciones"""
    return await proxy_request("notifications", path, request)

@app.api_route("/search/{path:path}", methods=["GET"])
async def search_route(path: str, request: Request):
    """Proxifica peticiones al servicio de búsqueda"""
    return await proxy_request("search", path, request)

@app.api_route("/integrations/{path:path}", methods=["GET", "POST", "PUT", "DELETE"])
async def integrations_route(path: str, request: Request):
    """Proxifica peticiones al servicio de integraciones"""
    return await proxy_request("integrations", path, request)
```

### Inter-Service Communication

- Use `httpx` for async HTTP calls between services
- Handle connection errors gracefully
- Pass correlation IDs for request tracing

### Error Handling

- Return appropriate HTTP status codes
- Include error details in response body
- Log errors with context

### Testing

- Include example requests in docstrings for FastAPI interactive docs (`/docs`)
- Test inter-service communication
- Verify MongoDB operations

## Practice Requirements (from PDF 6.2)

This implementation must satisfy:

1. ✅ **At least 2 parametrized search operations per entity**
   - Each service implements 2+ search endpoints with parameters
   
2. ✅ **At least 2 operations using entity relationships**
   - CalendarService: hierarchy queries
   - EventService: user-comment relationships
   - SearchService: cross-entity queries

3. ✅ **OpenAPI documentation**
   - Auto-generated by FastAPI from docstrings

4. ✅ **Docker containerization**
   - All services in Docker containers
   - docker-compose.yml for orchestration

5. ✅ **Non-relational database design**
   - MongoDB schema defined above
   - Justification in technical documentation
