# Basmati Backend Development Guide

## Project Overview

Basmati is a web-based calendar and event management application similar to Teamup. This guide covers **backend development only** using a microservices architecture.

## Technology Stack

- **Language**: Python 3.11+
- **API Framework**: FastAPI
- **Database**: MongoDB Atlas (cloud)
- **Deployment**: Docker (all services containerized)
- **Code Style**: snake_case for methods and variables
- **Documentation**: English for code, Spanish for comments

## Development Requirements

### General Rules

1. **Everything must be dockerized** - each microservice runs in its own container
2. **Each microservice must run on a different port**
3. **All methods must have docstrings** with:
   - Parameter descriptions
   - Return value descriptions and exceptions
   - Comments in Spanish, code in English
4. **OpenAPI specification** auto-generated by FastAPI
5. **MongoDB connection string** provided via environment variables
6. **Use Python 3.11+ modern syntax**:
   - Type hints with `|` (union types): `str | None` instead of `Optional[str]`
   - Generic types: `list[str]`, `dict[str, int]` instead of `List[str]`, `Dict[str, int]`
   - Pydantic v2: `model_config = ConfigDict(...)` instead of `class Config:`
   - Custom validators: `__get_pydantic_core_schema__()` instead of `__get_validators__()`
   
   **Example:**
   ```python
   # ✅ Correct (Python 3.11+)
   async def get_user(self, user_id: str) -> UserResponse | None:
       pass
   
   async def search_by_name(self, name: str) -> list[UserResponse]:
       pass
   
   class UserModel(BaseModel):
       id: PyObjectId | None = Field(alias="_id", default=None)
       followed_calendar_ids: list[PyObjectId] = Field(default_factory=list)
       
       model_config = ConfigDict(
           populate_by_name=True,
           arbitrary_types_allowed=True
       )
   
   # ❌ Avoid (legacy Python 3.9 syntax)
   # Optional[UserResponse], List[UserResponse], Dict[str, int]
   # class Config: ... in Pydantic models
   ```

7. **Define example requests in Pydantic schemas**:
   - Use `model_config = ConfigDict(json_schema_extra={...})` to add example payloads
   - Examples appear automatically in FastAPI `/docs` interactive documentation
   - Use realistic data for examples
   
   **Example:**
   ```python
   class UserCreate(BaseModel):
       """Schema base de usuario"""
       external_id: str = Field(..., description="ID del proveedor OAuth")
       provider: Literal["google", "facebook"] = Field(..., description="Proveedor OAuth")
       email: EmailStr = Field(..., description="Email del usuario")
       display_name: str = Field(..., description="Nombre visible del usuario")
       
       model_config = ConfigDict(
           json_schema_extra={
               "example": {
                   "external_id": "google_123456789",
                   "provider": "google",
                   "email": "juan@example.com",
                   "display_name": "Juan Pérez"
               }
           }
       )
   ```

## Database Schema (MongoDB Atlas)

### Collections

#### `users`
```python
{
    "_id": ObjectId,
    "external_id": str,  # unique - OAuth provider ID (Google ID, Facebook ID, etc.)
    "provider": str,  # "google" or "facebook"
    "email": str,
    "display_name": str,
    "avatar_url": str | None,
    "notification_preferences": {
        "in_app": bool,
        "email": bool,
        "email_address": str | None  # alternative email for notifications
    },
    "followed_calendar_ids": list[ObjectId],
    "created_at": datetime,
    "last_login": datetime | None
}
```

#### `calendars`
```python
{
    "_id": ObjectId,
    "title": str,
    "creator_external_id": str,  # reference to users.external_id
    "creator_display_name": str,  # denormalized for performance
    "keywords": list[str],
    "color": str,  # HEX format (#RRGGBB)
    "icon": str | None,
    "parent_calendar_id": ObjectId | None,  # for hierarchical calendars
    "path": list[ObjectId],  # array of ancestor IDs for efficient hierarchy queries
    "description": str | None,
    "visibility": str,  # "public", "private", or "unlisted"
    "created_at": datetime,
    "updated_at": datetime,
    "subscriber_count": int  # denormalized counter
}
```

#### `events`
```python
{
    "_id": ObjectId,
    "calendar_id": ObjectId,  # reference to calendars
    "calendar_title": str,  # denormalized for views without joins
    "creator_external_id": str,  # reference to users.external_id
    "title": str,
    "description": str | None,
    "start_time": datetime,
    "end_time": datetime,
    "location": {  # structured location data
        "address": str,
        "latitude": float,  # -90 to 90
        "longitude": float,  # -180 to 180
        "place_name": str | None,
        "map_provider": str  # "google_maps" or "openstreetmap"
    } | None,
    "attachments": list[{
        "_id": ObjectId,
        "filename": str,
        "url": str,  # URL to Google Cloud Storage
        "size": int,  # bytes
        "mime_type": str,
        "uploaded_at": datetime,
        "uploaded_by": str,  # external_id
        "is_image": bool,
        "thumbnail_url": str | None
    }],
    "comments": list[{
        "_id": ObjectId,
        "author_external_id": str,
        "author_display_name": str,
        "text": str,
        "created_at": datetime
    }],
    "visibility": str,  # "public", "private", or "inherited"
    "recurrence": {  # for recurring events
        "pattern": str,  # "daily", "weekly", "monthly", "yearly"
        "interval": int,  # every N units
        "days_of_week": list[int] | None,  # 0=Sunday, 6=Saturday
        "end_date": datetime | None,
        "exceptions": list[datetime]  # dates to skip
    } | None,
    "created_at": datetime,
    "updated_at": datetime
}
```

#### `notifications`
```python
{
    "_id": ObjectId,
    "recipient_external_id": str,  # reference to users.external_id
    "type": str,  # "NEW_COMMENT", "EVENT_UPDATE", "CALENDAR_INVITE", "EVENT_REMINDER"
    "title": str,
    "message": str,
    "is_read": bool,
    "related_event_id": ObjectId | None,
    "related_calendar_id": ObjectId | None,
    "created_at": datetime,
    "expires_at": datetime | None  # for automatic cleanup with TTL index
}
```

## Microservices Architecture

### 0. API Gateway (Port 8000)

**Responsibilities**:
- Single entry point for all client requests
- Request routing to appropriate microservices
- Request/response validation
- Cross-cutting concerns (logging, error handling)

**Features**:
- Routes all API requests to backend services
- Centralizes API versioning (`/v1/`, `/v2/`)
- Aggregates responses from multiple services
- Handles request/response transformation

**Required Endpoints**:
- All endpoints are proxied to backend services
- `GET /docs` - FastAPI interactive documentation
- Health check: `GET /health`

**Environment Variables**:
- `SERVICE_PORT=8000`
- `USER_SERVICE_URL=http://user-service:8001`
- `CALENDAR_SERVICE_URL=http://calendar-service:8002`
- `EVENT_SERVICE_URL=http://event-service:8003`
- `NOTIFICATION_SERVICE_URL=http://notification-service:8004`
- `SEARCH_SERVICE_URL=http://search-service:8005`
- `INTEGRATION_SERVICE_URL=http://integration-service:8006`

---

### 1. UserService (Port 8001)

**Responsibilities**:
- User CRUD operations
- User preference management
- Basic user profile queries

**Required Endpoints**:
- `POST /users` - Create user (with OAuth external_id and provider)
- `GET /users/{user_id}` - Get user by ID
- `PUT /users/{user_id}` - Update user
- `DELETE /users/{user_id}` - Delete user
- `GET /users/search?email={email}` - Search by email (parametrized query 1)
- `GET /users/search?display_name={name}` - Search by partial display name (parametrized query 2)
- `GET /users/search?external_id={id}&provider={provider}` - Search by OAuth credentials

**Environment Variables**:
- `MONGO_URI`
- `SERVICE_PORT=8001`

---

### 2. CalendarService (Port 8002)

**Responsibilities**:
- Calendar CRUD operations
- Hierarchical calendar relationships
- Calendar search and filtering

**Required Endpoints**:
- `POST /calendars` - Create calendar
- `GET /calendars/{calendar_id}` - Get calendar by ID
- `PUT /calendars/{calendar_id}` - Update calendar (only by creator)
- `DELETE /calendars/{calendar_id}` - Delete calendar (only by creator)
- `GET /calendars/search?creator_external_id={external_id}` - Get calendars by creator (parametrized query 1)
- `GET /calendars/search?keywords={keyword}` - Search by keywords (parametrized query 2)
- `GET /calendars/search?visibility={visibility}` - Filter by visibility (public/private/unlisted)
- `GET /calendars/{calendar_id}/children` - Get child calendars (relationship query 1)
- `GET /calendars/{calendar_id}/hierarchy` - Get full calendar hierarchy using path array (relationship query 2)

**Environment Variables**:
- `MONGO_URI`
- `SERVICE_PORT=8002`
- `USER_SERVICE_URL=http://user-service:8001`

---

### 3. EventService (Port 8003)

**Responsibilities**:
- Event CRUD operations
- Event content management (attachments, comments)
- Trigger notifications on comments

**Required Endpoints**:
- `POST /events` - Create event
- `GET /events/{event_id}` - Get event by ID
- `PUT /events/{event_id}` - Update event
- `DELETE /events/{event_id}` - Delete event
- `POST /events/{event_id}/comments` - Add comment (triggers notification)
- `POST /events/{event_id}/attachments` - Add attachment URL
- `GET /events/search?calendar_id={calendar_id}` - Get events by calendar (parametrized query 1)
- `GET /events/search?date_range?start={start}&end={end}` - Get events by date range (parametrized query 2)
- `GET /events/{event_id}/comments/users` - Get users who commented on event (relationship query 1)
- `GET /users/{user_id}/commented_events` - Get events user commented on (relationship query 2)

**Environment Variables**:
- `MONGO_URI`
- `SERVICE_PORT=8003`
- `NOTIFICATION_SERVICE_URL=http://notification-service:8004`
- `CALENDAR_SERVICE_URL=http://calendar-service:8002`

---

### 4. NotificationService (Port 8004)

**Responsibilities**:
- Create and manage notifications
- Send email notifications
- Mark notifications as read

**Required Endpoints**:
- `POST /notifications` - Create notification (called by EventService)
- `GET /notifications/user/{external_id}` - Get user notifications by external_id
- `PUT /notifications/{notification_id}/read` - Mark as read
- `GET /notifications/search?recipient_external_id={external_id}&is_read=false` - Get unread notifications (parametrized query 1)
- `GET /notifications/search?related_event_id={event_id}` - Get notifications for specific event (parametrized query 2)
- `GET /notifications/search?type={type}` - Filter by notification type

**Environment Variables**:
- `MONGO_URI`
- `SERVICE_PORT=8004`
- `USER_SERVICE_URL=http://user-service:8001`
- `EMAIL_SERVICE_API_KEY` (optional for now)

---

### 5. SearchService (Port 8005)

**Responsibilities**:
- Advanced search across calendars and events
- Indexing for efficient queries
- Aggregated search results

**Required Endpoints**:
- `GET /search/calendars?q={query}` - Full-text search calendars (parametrized query 1)
- `GET /search/events?q={query}` - Full-text search events (parametrized query 2)
- `GET /search/combined?q={query}` - Search both calendars and events
- `GET /search/calendars/by_creator?creator_name={name}` - Find calendars by creator name (relationship query 1)
- `GET /search/events/by_calendar_title?title={title}` - Find events by calendar title (relationship query 2)
- `GET /search/events/by_location?query={location}` - Search events by location

**Environment Variables**:
- `MONGO_URI`
- `SERVICE_PORT=8005`
- `CALENDAR_SERVICE_URL=http://calendar-service:8002`
- `EVENT_SERVICE_URL=http://event-service:8003`

---

### 6. IntegrationService (Port 8006)

**Responsibilities**:
- Import calendars from external APIs (Google Calendar, Teamup)
- Synchronize external events
- Handle external API authentication

**Required Endpoints**:
- `POST /integrations/google/import` - Import from Google Calendar
- `POST /integrations/teamup/import` - Import from Teamup
- `GET /integrations/sources?external_id={external_id}` - Get user's integrated sources (parametrized query 1)
- `GET /integrations/sync_status?source_id={source_id}` - Get sync status (parametrized query 2)

**Environment Variables**:
- `MONGO_URI`
- `SERVICE_PORT=8006`
- `CALENDAR_SERVICE_URL=http://calendar-service:8002`
- `EVENT_SERVICE_URL=http://event-service:8003`
- `GOOGLE_CALENDAR_API_KEY` (optional for now)
- `TEAMUP_API_KEY` (optional for now)

---


## Practice Requirements (from PDF 6.2)

This implementation must satisfy:

1. ✅ **At least 2 parametrized search operations per entity**
   - Each service implements 2+ search endpoints with parameters
   
2. ✅ **At least 2 operations using entity relationships**
   - CalendarService: hierarchy queries
   - EventService: user-comment relationships
   - SearchService: cross-entity queries

3. ✅ **OpenAPI documentation**
   - Auto-generated by FastAPI from docstrings

4. ✅ **Docker containerization**
   - All services in Docker containers
   - docker-compose.yml for orchestration

5. ✅ **Non-relational database design**
   - MongoDB schema defined above
   - Justification in technical documentation
